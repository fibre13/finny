# Библиотеки, шрифты, изображения, звуки и лицензии

Пункт 12 раздела 5 ТЗ. Перечень составлен на версии 0.9.0 (versionCode 18). Разделы 1–3 описывают библиотеки версии 0.9.0; выгрузка состава (раздел 8) повторена на версии 0.9.0, проверка уязвимостей (разделы 9–10) выполнена на версии 0.5.0: перечень зависимостей в `gradle/libs.versions.toml` и `app/gradle.lockfile` с тех пор не менялся. Разделы 4 и 5 описывают шрифт, пиктограммы и графику версии 0.9.0.

## 1. Как получен перечень

Состав релизной сборки взят у самой сборки, а не выписан из файлов зависимостей:

```
gradlew :app:dependencies --configuration releaseRuntimeClasspath
```

В классе путей выполнения релиза 117 уникальных артефактов. Лицензия каждого прочитана из его файла описания (`.pom`) в локальном кэше Gradle: разбирался блок `<licenses>`.

Итог разбора:

| Формулировка в описании артефакта | Артефактов |
|---|---|
| The Apache Software License, Version 2.0 | 112 |
| Apache-2.0 | 8 |
| The Apache License, Version 2.0 | 2 |

Три записи — разные написания одной лицензии Apache License 2.0.

Один артефакт, `com.google.guava:listenablefuture:1.0`, собственного блока лицензии не имеет: он наследует его от родительского описания `com.google.guava:guava-parent:26.0-android`, где объявлено:

```xml
<licenses>
    <license>
      <name>The Apache Software License, Version 2.0</name>
      <url>http://www.apache.org/licenses/LICENSE-2.0.txt</url>
      <distribution>repo</distribution>
    </license>
  </licenses>
```

Сам артефакт содержит один класс `ListenableFuture` и приходит транзитивно через AndroidX; напрямую проект его не объявляет.

**Вывод: все 117 артефактов, попадающих в APK, распространяются под Apache License 2.0.** Лицензий с требованием раскрытия исходного кода производного продукта (GPL, LGPL, AGPL) среди них нет.

## 4. Шрифты

В приложение включён шрифт Inter: три файла в `app/src/main/res/font/`.

| Файл | Начертание | Размер, байт |
|---|---|---|
| `inter_regular.ttf` | 400 | 114 144 |
| `inter_bold.ttf` | 700 | 114 440 |
| `inter_extrabold.ttf` | 800 | 114 804 |

Файлы получены из вариативного шрифта Inter: выделены статические начертания 400, 700 и 800 с оптическим размером 14 и подмножеством знаков для русского и латинского алфавитов. Вариативный файл на Android 8.0 давал разрывы между буквами в полужирном тексте, поэтому используется статический вариант.

Лицензия — SIL Open Font License 1.1. Текст лицензии с уведомлением об авторских правах («Copyright 2016 The Inter Project Authors», как в метаданных поставляемых файлов шрифта Inter версии 4.001) хранится в репозитории в файле docs/inter-OFL.txt. OFL допускает включение шрифта в приложение и изменённые версии шрифта; изменённая версия не должна называться зарезервированным именем. Зарезервированных имён в лицензии Inter не объявлено.

## 5. Изображения и пиктограммы

Растровых файлов в исходниках приложения нет: каталог ресурсов `app/src/main/res` содержит 12 файлов — векторную разметку значка приложения, три файла шрифта и описания значений.

Графика приложения построена тремя способами.

1. **Собственная пиксельная графика.** Питомец трёх видов на трёх стадиях, мимика, украшения (бантик, шарфик, шапочка), сцена двора, палатка, цели, предметы двора, картинки к заданиям, значки событий дня, товаров-сюрпризов, терминов словарика и праздника роста. Исходники — файлы в `art/pixel/src/` (185 файлов: 182 рисунка, палитра `palette.txt` и два файла настроек `anchors.json` и `animation.json`): каждый рисунок записан сеткой символов палитры `art/pixel/src/palette.txt`. Сборка в файл контента `content/src/main/assets/pixel_art.json` выполняется скриптом `art/pixel/tools/build.py`; предметы двора и картинки к заданиям порождаются скриптами `art/pixel/tools/make_yard.py` и `art/pixel/tools/make_items.py`, значки интерфейса и товаров лавки (стрелки «назад» и «открыть», крестик закрытия сообщения, флажок цели, товары 16 × 16) — скриптом `art/pixel/tools/make_icons.py`, значки сезона — скриптом `art/pixel/tools/make_icons_season.py`. Вся пиксельная графика нарисована авторами проекта; сторонних наборов значков в приложении нет. Авторы проекта перечислены в README, раздел «Авторы».

2. **Пиктограммы, нарисованные кодом** (`app/src/main/kotlin/ru/onefortwo/finny/ui/common/Pictograms.kt`): лицо уровня показателя, галочка и знак внимания результата задания, монета — простая геометрия (окружности, линии, дуги), построенная авторами проекта.
3. **Векторные ресурсы Android.** Значок приложения: `ic_launcher_foreground.xml`, `ic_launcher_monochrome.xml` и описания адаптивного значка — разметка, написанная авторами проекта. Иконка карточки RuStore `docs/rustore/icon-512.png` собрана из того же вектора.

Растровых изображений, полученных генерацией, в проекте нет.

Скрипт `make_icons_season.py` описывает 38 значков 16 × 16 в той же палитре и записывает их исходниками `art/pixel/src/yard/item_*.txt`; существующие файлы он не перезаписывает. Все 38 значков собраны в `pixel_art.json`. Группы значков:

## 8. Состав сборки в машиночитаемом виде (SBOM)

Тот же состав выгружен в формате CycloneDX 1.5 в файл docs/sbom/finny-0.9.0-cyclonedx.json (версия 0.9.0, versionCode 18, выгрузка 29 сентября 2026 командой `python scripts/sbom.py`); файл версии 0.5.0 сохранён для истории, состав компонентов в обоих файлах совпадает. Для каждого из 117 компонентов записаны координаты, идентификатор `purl`, лицензия и контрольные суммы SHA-1 и SHA-256 двоичного файла.

Техническое задание SBOM не требует. Он сделан потому, что данные для него уже собраны, а критерий 8.2 оценивает воспроизводимость сборки: по этому файлу состав релиза проверяется без пересборки проекта.

Перечень строится скриптом scripts/sbom.py:

```
python scripts/sbom.py
```

Скрипт спрашивает состав у самой сборки, читает лицензии из описаний артефактов и считает суммы по файлам в кэше Gradle. Плагин для выгрузки сознательно не подключался: он добавил бы зависимость сборки ради документа, который собирается из уже доступных данных.

Три компонента из 117 — спецификации согласованных версий (`compose-bom`, `kotlinx-coroutines-bom`, `kotlinx-serialization-bom`); собственного двоичного файла у них нет, поэтому и контрольных сумм тоже. В перечне они помечены типом `framework`.

## 9. Как закреплены версии

| Свойство | Состояние |
|---|---|
| Версии зависимостей | Закреплены точно в `gradle/libs.versions.toml`; динамических версий и диапазонов нет |
| Объявлено напрямую | 14 библиотек и спецификация версий `compose-bom` в модулях `app` и `data`, а также `kotlin-stdlib`, добавляемая плагином Kotlin; остальные 101 артефакт приходят транзитивно |
| Разрешение конфликтов версий | Повышение до более новой версии при совпадающих группах — стандартное поведение Gradle; итоговые версии записаны в файле блокировок |
| Источники | `google()` и `mavenCentral()`; для плагинов доступ к `google()` ограничен группами `com.android.*`, `com.google.*`, `androidx.*` |
| Файл блокировок Gradle | `app/gradle.lockfile` для `releaseRuntimeClasspath` |
| Проверка контрольных сумм при разрешении зависимостей | Не настроена |

Все 117 разрешённых версий записаны явно в файле блокировок, поэтому состав релиза виден в изменениях, а не выводится разрешением при каждой сборке.

Закреплена только конфигурация `releaseRuntimeClasspath` — то, что уходит пользователю. `lockAllConfigurations()` захватил бы у Android-проекта десятки конфигураций, включая тестовые и вспомогательные, и ломался бы чаще, чем приносил пользы.

**Как добавить или обновить зависимость.** Правка каталога версий сама по себе остановит сборку:

```
> Resolved 'androidx.webkit:webkit:1.12.1' which is not part of the dependency lock state
```

Состояние пересобирается одной командой, после чего файл блокировок коммитится вместе с правкой:

```
gradlew :app:dependencies --configuration releaseRuntimeClasspath --write-locks
```

Для точечного обновления одной библиотеки есть `--update-locks группа:модуль`. Та же команда попутно обновляет `settings-gradle.lockfile` — пустое состояние для каталога версий.

Проверка: временно добавленная зависимость `androidx.webkit` остановила сборку приведённым выше сообщением, после отката сборка прошла.

## 10. Проверка на известные уязвимости

Проводится скриптом scripts/audit.py по базе [OSV](https://osv.dev) — открытой базе уязвимостей, сводящей в том числе GitHub Advisory Database. Ключ доступа не нужен.

```
python scripts/audit.py
```

Результат последней проверки — файл docs/sbom/audit-0.5.0.md: уязвимостей в составе релизной сборки не найдено.

**Пустой результат подтверждается контрольной пробой.** В тот же запрос добавляется заведомо уязвимая версия `org.apache.logging.log4j:log4j-core:2.14.1`; база возвращает по ней 7 записей. Если проба не срабатывает, скрипт останавливается с ошибкой вместо вывода «ничего не найдено»: иначе сломанный запрос было бы не отличить от чистого состава.

Границы проверки: проверяется только то, что попадает в APK — средства сборки и зависимости тестов до устройства не доходят; проверка показывает известное базе на дату запуска; собственный код приложения ею не охватывается.

Наружу при проверке уходят только координаты библиотек с открытым исходным кодом и их версии — то же, что уже записано в SBOM и файле блокировок.

## 11. Ограничение этого перечня

Лицензии транзитивных зависимостей прочитаны из описаний артефактов в локальном кэше Gradle. Это то, что объявляют сами авторы библиотек; юридическая проверка текстов лицензий не проводилась.
