# Подпись релизной сборки

Ключ подписи создаётся один раз и хранится вне репозитория. Пароли к нему не должны попадать ни в файлы проекта, ни в какую-либо переписку: генерирует ключ и вводит пароли тот, кто будет управлять релизом.

## 1. Создание ключа

Выполните команду в своём терминале (PowerShell):

```powershell
cd <корень репозитория>
mkdir keystore
& ".\tools\jdk17\bin\keytool.exe" -genkeypair -v `
    -keystore keystore\finny-release.jks `
    -alias finny `
    -keyalg RSA -keysize 2048 -validity 10000
```

`keytool` запросит интерактивно:

| Запрос | Что ввести |
|---|---|
| Пароль хранилища ключей | Придумайте пароль, запомните или сохраните в менеджере паролей |
| Повтор пароля | Тот же пароль |
| Имя и фамилия | Можно указать название команды или проекта |
| Название организационного подразделения | Можно оставить пустым (Enter) |
| Название организации | Название команды или организации-участника конкурса |
| Город, регион, код страны | По желанию, можно оставить пустым |
| Подтверждение данных | `yes` |
| Пароль для ключа `finny` | Enter — совпадёт с паролем хранилища; либо введите отдельный пароль |

Срок действия `-validity 10000` — это примерно 27 лет, стандартная практика для Android: смена ключа означает невозможность обновить ранее опубликованное приложение, поэтому запас берётся с большим избытком.

Результат — файл `keystore\finny-release.jks`. Он уже подпадает под правило `*.jks` в `.gitignore` и не будет закоммичен, даже если лежит внутри репозитория.

## 2. Файл с параметрами

Скопируйте шаблон и заполните паролями, которые вы только что придумали:

```powershell
Copy-Item keystore.properties.example keystore.properties
notepad keystore.properties
```

Файл должен выглядеть так (пример, не настоящие пароли):

```
storeFile=keystore/finny-release.jks
storePassword=ваш-пароль-хранилища
keyAlias=finny
keyPassword=ваш-пароль-ключа
```

Файл `keystore.properties` уже в `.gitignore`. Заполненный файл никуда не пересылайте — держите его локально или в отдельном защищённом хранилище, отдельно от репозитория.

## 3. Сборка подписанного релиза

После того как `keystore.properties` заполнен, обычная команда сборки релиза автоматически подпишет APK:

```powershell
. scripts/env.ps1
./gradlew.bat assembleRelease
```

Готовый файл: `app/build/outputs/apk/release/app-release.apk` (без суффикса `-unsigned`, если подпись применилась).

Проверить подпись:

```powershell
& "$env:ANDROID_HOME\build-tools\37.0.0\apksigner.bat" verify --verbose app/build/outputs/apk/release/app-release.apk
```

Ожидаемый результат содержит строку `Verified using v2 scheme` или `v3 scheme` и `Verified` без ошибок.

## 4. Если keystore.properties отсутствует

Сборка `assembleRelease` не падает: `app/build.gradle.kts` проверяет наличие `keystore.properties` и, если файла нет, собирает `app-release-unsigned.apk` как раньше. Это позволяет любому участнику команды или системе сборки собирать проект без доступа к ключу — подписание нужно только для финальной сдачи и публикации в RuStore.

## 5. Резервное копирование ключа

Файлы `keystore\finny-release.jks` и `keystore.properties` не восстанавливаются, если их потерять: обновить уже установленное у экспертов приложение станет невозможно. Сохраните копию ключа и пароли в надёжном месте отдельно от репозитория — например, в менеджере паролей команды.

## 6. Версия и номер сборки при следующих релизах

Перед каждой новой сдачей увеличивайте оба значения в `app/build.gradle.kts`: `versionCode` — на единицу при каждой сборке, которая отдаётся на проверку, `versionName` — человекочитаемая версия. Оба значения фиксируются в сопроводительной документации (ТЗ 3.3).

Текущие значения в `app/build.gradle.kts`:

```kotlin
versionCode = 5
versionName = "0.3.2"
```

Понижение `versionCode` Android не допускает: установка сборки с меньшим номером поверх большего завершается ошибкой `INSTALL_FAILED_VERSION_DOWNGRADE`. Если номер был повышен во время проверки обновления, возврат к прежнему значению потребует удаления пакета вместе с данными.

## 7. Фактическая проверка

Ключ создан, `assembleRelease` собрал подписанный `app-release.apk` (8763 КБ) без суффикса `-unsigned`.

Проверка `apksigner verify --verbose --print-certs`:

```
Verifies
Verified using v2 scheme (APK Signature Scheme v2): true
V2 Signer: key algorithm: RSA
V2 Signer: key size (bits): 2048
```

Установка на эмулятор Android 8.0 пакета `ru.onefortwo.finny` (без суффикса `.debug`) прошла как первая установка, что подтверждает: на устройстве ранее не стоял пакет с другой подписью. Запуск:

```
adb shell am start -W -n ru.onefortwo.finny/ru.onefortwo.finny.MainActivity
Status: ok
TotalTime: 341
```

Записей об аварийном завершении приложения в журнале нет. Версия установленного пакета: `versionCode=1`, `versionName=0.1.0` — совпадала с `app/build.gradle.kts` на момент этой проверки.

## 8. Проверка версии 0.2.0

Сборка versionCode 2 / versionName 0.2.0 подписана тем же ключом и установлена поверх версии 0.1.0 без удаления данных. Вывод `apksigner verify`, отпечатки сертификата и открытого ключа, результат установки и запуска — в [docs/03-проверка-на-устройстве.md](03-проверка-на-устройстве.md), разделы «Проверка обновления с сохранением прогресса на релизной сборке» и «Подпись релизной сборки 0.2.0».

Установка поверх пакета, подписанного другим ключом, Android отклоняет, поэтому успешная установка обновления одновременно подтверждает неизменность ключа подписи.

## 9. Проверка версии 0.3.1

Сборка versionCode 4 / versionName 0.3.1 подписана тем же ключом и установлена поверх версии 0.3.0 без удаления данных. Отпечаток сертификата `f11ca9b9…9459af7` совпадает с отпечатками версий 0.2.0 и 0.3.0. Вывод `apksigner verify`, показания прогресса до и после обновления, результат установки и запуска — в [docs/03-проверка-на-устройстве.md](03-проверка-на-устройстве.md), раздел «Релизная сборка 0.3.1».

## 10. Проверка версии 0.7.0

Сборка versionCode 16 / versionName 0.7.0 подписана тем же ключом. Вывод `apksigner verify --print-certs` для `app/build/outputs/apk/release/app-release.apk`, отфильтрованный по строкам сертификата:

```
V2 Signer: certificate DN: CN=OneForTwo, OU=Unknown, O=Unknown, L="Russia, DC", ST=Unknown, C=RU
V2 Signer: certificate SHA-256 digest: f11ca9b92ac5340f8471717b997238324817b2fa43536ac2db98c4a9b9459af7
```

Отпечаток сертификата совпадает с отпечатком, записанным для версий 0.2.0, 0.3.0 и 0.3.1. Установка релиза 0.7.0 поверх установленного релиза на физическом устройстве на момент записи не выполнена — см. раздел «Незавершённые проверки» в [docs/03-проверка-на-устройстве.md](03-проверка-на-устройстве.md).
