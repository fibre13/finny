# Функциональная и компонентная архитектура

Документ выполняет пункт 5.3 технического задания. Серверной части нет (ТЗ 3.2): приложение работает полностью на устройстве, поэтому схема развёртывания и спецификация OpenAPI не требуются.

## 1. Функциональная архитектура

Приложение состоит из игрового цикла одного дня и вспомогательных разделов. Двор — главный экран; разделы открываются предметами на лугу и значками в шапке.

| Функция | Что делает ребёнок или взрослый | Экран | Правила |
|---|---|---|---|
| Знакомство и профиль | Открывает подарок, выбирает вид, окрас и украшения, придумывает игровое имя и уровень заданий | `GiftScreen`, `PetSetupScreen` | `NameFilter`, `Difficulty` |
| Двор | Видит день, имя, баланс, самочувствие питомца и предметы-разделы; следует подсказке первого дня | `YardScreen` | `YardGuide`, `PetSpeech` |
| План бюджета | Распределяет монеты дня на «Нужное», «Хочу» и «Копим на мечту»; после утверждения видит «План и факт» | `PlanScreen` | `GameState.confirmPlan`, `Budget` |
| Покупки | Покупает нужное и желаемое, видит цену, направление и пользу; при нехватке — варианты действий | `ShopScreen` | `GameState.buy`, `Shop` |
| Копилка и цель | Выбирает мечту, пополняет копилку, видит срок, снимает с подтверждением, получает накопленную цель | `SavingsScreen` | `Savings`, `SavingsState.forecast` |
| Задания | Решает задания четырёх типов, получает объяснение и награду | `TasksScreen`, `TaskDetailScreen` | `TaskChecking`, `TaskQueue`, `TaskVariation`, `TaskPay` |
| Итоги дня | Видит шаги роста, план и факт, изменение самочувствия, стадию; закрывает день | `PeriodResultScreen` | `GameState.finishPeriod`, `Period`, `Pet` |
| Гардероб | Меняет окрас и надевает купленные украшения | `WardrobeScreen` | `Accessories` |
| Мой прогресс | Смотрит историю дней и полученные цели | `HistoryScreen` | — |
| Словарик | Читает 11 финансовых терминов | `GlossaryScreen` | — |
| Как играть | Перечитывает цель игры и три решения | `OnboardingScreen` | — |
| Раздел для взрослого | Проходит барьер, видит, чему учит игра, прогресс, настраивает экранное время и движения, включает демонстрационный режим, сбрасывает профиль | `AdultScreen` | `ScreenTime`, `GameViewModel.resetProfile` |

Последовательность экранов повторяет сквозной сценарий Приложения А ТЗ: подарок → питомец и имя → двор с окном «Пришли монеты» → цель → план → покупки → задание → покупка желаемого → «Закончить день» → итоги → новый день.

## 2. Модули

Проект разделён на четыре модуля Gradle. Правила экономики не зависят от Android и проверяются модульными тестами на JVM.

```
                ┌──────────────────────────────┐
                │ app                          │
                │ экраны Compose, навигация,   │
                │ GameViewModel, AppState      │
                └──────┬───────────┬───────────┘
                       │           │
          ┌────────────▼───┐   ┌───▼────────────┐
          │ content        │   │ data           │
          │ JSON-контент,  │   │ Room: сущности,│
          │ проверка       │   │ DAO, переходы  │
          │ ответов, имя,  │   │ схемы, запись  │
          │ графика        │   │ и чтение игры  │
          └────────┬───────┘   └───────┬────────┘
                   │                   │
                ┌──▼───────────────────▼──┐
                │ core-economy            │
                │ чистый Kotlin: баланс,  │
                │ план, покупки, копилка, │
                │ питомец, день, доход    │
                └─────────────────────────┘
```

Зависимости (из `build.gradle.kts` модулей): `app` → `core-economy`, `content`, `data`; `content` → `core-economy` (`api`); `data` → `core-economy` (`api`). Обратных зависимостей нет.

## 3. Компоненты модулей

### core-economy — правила экономики

| Файл | Ответственность |
|---|---|
| `Money.kt` | Тип `Coins`: целые монеты без отрицательного баланса |
| `Budget.kt` | Направления `BudgetCategory` («Нужное», «Хочу», «Копим на мечту»), план дня и проверка суммы |
| `Shop.kt` | Позиции каталога, направление покупки, влияние на показатель |
| `Savings.kt` | Цель, копилка, взнос и снятие, срок достижения по средним взносам |
| `Pet.kt` | Показатели «Забота» и «Радость», уровни, стадии развития, снижение за день |
| `Period.kt` | Итог дня: шаги роста, план и факт, неудачный день, доход следующего дня |
| `Income.kt` | Источники дохода и суммы: стартовый бюджет, карманные, награды |
| `Difficulty.kt` | Уровень заданий «Попроще» или «Посложнее» |
| `GameState.kt` | Неизменяемое состояние игры и переходы: план, покупка, взнос, снятие, завершение дня, новый день |

Каждое действие — чистая функция: принимает состояние и возвращает новое состояние с событием или отказом с причиной. Благодаря этому одни и те же правила проверяются тестами и исполняются приложением.

### content — учебный контент и графика

| Файл | Ответственность |
|---|---|
| `ContentRepository.kt` | Чтение и кеширование JSON из `assets`: задания, каталог, цели, внешность, словарик, запрещённые слова, пиксельная графика |
| `ContentParser.kt`, `ContentModels.kt`, `ContentMapping.kt` | Разбор JSON и перевод в модели `core-economy` |
| `TaskModels.kt` | Типы заданий: `AllocateTask`, `PickTask`, `NumberTask`, `ChoiceTask`; темы и уровни |
| `TaskVariation.kt` | Переменные числа заданий по описанию `vary` |
| `TaskChecking.kt` | Проверка ответа, объяснение и сумма награды |
| `TaskQueue.kt` | Порядок выдачи заданий по кругу тем, повтор, разделы списка |
| `NameFilter.kt` | Проверка игрового имени по списку `forbidden_words.json` |
| `PetAppearance.kt` | Внешность питомца и набор украшений `Accessories` |
| `PixelArt.kt` | Модель пиксельной графики из `pixel_art.json` |

### data — хранение

| Файл | Ответственность |
|---|---|
| `Entities.kt` | Восемь таблиц Room (состав — в docs/02, раздел «Хранение данных») |
| `GameDao.kt` | Запросы чтения, записи и удаления |
| `FinnyDatabase.kt` | База Room версии 8, экспорт схем в `data/schemas` |
| `Migrations.kt` | Переходы схемы 1 → 8 без потери прогресса |
| `SavedGame.kt` | Перевод состояния игры в записи таблиц и обратно |
| `GameRepository.kt` | Загрузка, сохранение в одной транзакции, полное удаление профиля, настройки отображения |

### app — интерфейс и состояние

| Компонент | Ответственность |
|---|---|
| `MainActivity` | Точка входа, отображение от края до края, закрепление портретной ориентации на телефоне |
| `FinnyApp` | Граф навигации: маршруты `onboarding`, `pet_setup`, `main`, `plan`, `shop`, `tasks`, `task`, `savings`, `result`, `history`, `glossary`, `help`, `adult`, `wardrobe`; водяной знак демонстрационного режима |
| `GameViewModel` | Единственный держатель состояния: принимает действия экранов, вызывает правила `core-economy`, формирует сообщения, считает экранное время, записывает состояние |
| `AppState` | Неизменяемое состояние интерфейса: профиль, игра, сообщение, окно «Пришли монеты», решённые задания, экранное время, режим |
| `Explanations` | Все тексты обратной связи: причины, последствия, следующий шаг, склонения чисел |
| `YardGuide` | Шаг подсказки первого дня, вычисляемый из состояния |
| `PetSpeech`, `PetReaction` | Реплики и реакции питомца |
| `ui/screens/*` | Экраны разделов (таблица раздела 1) |
| `ui/common/*` | Общие компоненты: кнопки, карточки, отклик, пиктограммы, пиксельные изображения, движения питомца |
| `ui/theme/*` | Цвета, шрифт Inter, формы |

## 4. Поток данных

```
 экран ──действие──▶ GameViewModel ──▶ GameState (core-economy) ──▶ новое состояние
   ▲                      │                                            │
   │                      └──── Explanations: текст отклика ◀──────────┤
   │                                                                   ▼
   └──────────── StateFlow<AppState> ◀──────────────────────── AppState
                          │
                          └──▶ автосохранение: GameRepository.save (Room, одна транзакция)
```

1. Экран вызывает метод модели: например, `buy("food")`.
2. Модель применяет правило `GameState.buy`. Результат — новое состояние и событие или отказ с причиной (например, нехватка монет).
3. `Explanations` формирует сообщение: что изменилось, почему и что делать дальше.
4. Новое `AppState` публикуется через `StateFlow`; экраны перерисовываются.
5. Каждое изменение состояния записывается в базу (`GameViewModel`, блок автосохранения): прогресс переживает закрытие приложения (ТЗ 2.5.13).
6. При запуске модель читает сохранённую игру (`GameRepository.load`). Если профиля нет, открывается знакомство.

Учебный контент читается из `assets` один раз на процесс и в базу не записывается: новое задание добавляется записью в `tasks.json` без изменения кода (ТЗ 2.5.14).

## 5. Схема обновления учебного контента

1. Задание, товар, цель или термин добавляется записью в соответствующий JSON в `content/src/main/assets/`. Поля задания описаны в docs/01, раздел 7.
2. Картинка к заданию — существующий спрайт или новый исходник в `art/pixel/src/` со сборкой `art/pixel/tools/build.py`.
3. Автотесты `TaskContentTest`, `TaskQueueTest`, `TaskVariationTest`, `ContentFilesTest` проверяют полноту полей, темы на каждом уровне, пределы чисел для уровня «Попроще» и связность переменных чисел.
4. Новая сборка приложения доставляет контент пользователю через магазин приложений. Серверной доставки контента в прототипе нет.
