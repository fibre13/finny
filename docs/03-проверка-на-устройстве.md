# Проверка на устройстве Android 8.0

Журнал проверки сборки на эмуляторе Android 8.0 (API 26) — минимальной поддерживаемой версии по ТЗ 3.1.

## Условия проверки

| Параметр | Значение |
|---|---|
| Устройство | Эмулятор, образ `system-images;android-26;google_apis;x86_64` |
| Версия системы | Android 8.0.0, API 26 |
| Ускорение | WHPX (Windows Hypervisor Platform) |
| Сборка | `app-debug.apk`, versionName 0.1.0, установлена командой `adb install -r` |
| Виртуальное устройство | `finny_api26` |

Установка прошла без ошибок, результат команды установки: `Success`.

## Время запуска

Замер средствами системы:

```
adb shell am start -W -n ru.onefortwo.finny.debug/ru.onefortwo.finny.MainActivity
ThisTime: 349
TotalTime: 349
WaitTime: 365
```

Требование ТЗ 3.4 — не более 5 секунд до стартового экрана. Фактически 0,35 секунды.

Повторные замеры в течение сеанса: 559 мс при запуске с чтением сохранённого профиля, 336 мс после принудительной остановки приложения. Во всех случаях запуск укладывается в требование с большим запасом.

## Падения

За время прохождения сценария записей уровня `FATAL`, `AndroidRuntime` и `ANR`, относящихся к пакету приложения, в журнале не зафиксировано. Единственная запись `onFatalError` принадлежит стороннему процессу `com.google.android.googlequicksearchbox:search` и к приложению отношения не имеет.

## Проверка при увеличенном шрифте

Масштаб шрифта задавался системной настройкой командой `adb shell settings put system font_scale`, приложение перезапускалось после каждого изменения.

| Масштаб | Экраны | Результат |
|---|---|---|
| 1,3 | Главный, план, задания | Текст читается, строки переносятся, элементы не перекрываются |
| 1,5 | Главный, план, задания | Выявлено слипание подписи показателя «Радость: Спокойный ~» со значением «60 из 100» на главном экране |

Причина: подпись и значение располагались в строке с раскладкой по краям без ограничения ширины подписи. Исправление: подпись занимает свободную ширину и переносится, значение отделено фиксированным отступом. Повторная проверка на масштабе 1,5 после установки исправленной сборки: подпись перенесена на две строки, значение стоит отдельно. Снимки до и после: `docs/screenshots/fs1.5-before.png`, `docs/screenshots/fs1.5-after.png`.

## Проверка на физическом устройстве

Выполнена пользователем на планшете (ТЗ 3.1 п. 1, 3). Приложение работает корректно в портретной ориентации — это единственное обязательное требование к ориентации и размеру экрана (ТЗ 3.1 п. 2: «Обязательна корректная работа в портретной ориентации на экранах от 360 dp по ширине; поддержка планшетов и альбомной ориентации рассматривается как преимущество»).

На момент этой проверки ориентация была закреплена портретной. Позднее закрепление снято, в манифесте остался только `android:resizeableActivity="true"`, и поддержка обеих ориентаций проверена на эмуляторе планшета — раздел «Проверка поддержки планшетов и поворота экрана» ниже.

Проверка на телефоне выполнена отдельно и на актуальной версии — раздел «Проверка на физическом телефоне: Xiaomi MI 5» ниже. Именно она подтверждает требование ТЗ 3.1 п. 3 с указанием модели, версии Android и объёма оперативной памяти.

## Проверка поддержки планшетов и поворота экрана

Отдельный эмулятор `finny_tablet` на базе профиля Nexus 10: физическое разрешение 2560×1600, плотность 320, то есть 1280×800 dp — вчетверо больше площади телефонного экрана, на котором велась основная разработка.

| Проверка | Результат |
|---|---|
| Запуск в альбомной ориентации | Приложение открылось, 793 мс до главного экрана |
| Ширина содержимого | Колонка ограничена 640 dp и отцентрирована, строки текста не растягиваются на весь экран |
| Поворот в портрет и обратно | Приложение не перезапускается, экран не пустеет |
| Сохранение введённого имени питомца при повороте | Имя «Barsik» и выбранные вид, окрас, украшение сохранились |
| Сохранение результата задания при повороте | Экран с ответом «Верно», объяснением и суммой награды сохранился целиком |
| Падения при поворотах | Записей об аварийном завершении приложения в журнале нет |

Снимки: [tablet-landscape-main.png](screenshots/tablet-landscape-main.png), [tablet-portrait-main.png](screenshots/tablet-portrait-main.png).

**Что потребовалось изменить в коде.** Снятие закрепления портретной ориентации само по себе привело бы к дефекту: при каждом повороте Android пересоздаёт экран, и весь пользовательский ввод, хранившийся в обычной памяти композиции, обнулялся бы. Поэтому состояние ввода на всех экранах переведено на хранение, переживающее пересоздание: имя и внешность питомца, суммы плана бюджета, введённые числа и отметки в заданиях, суммы пополнения и снятия, состояние диалогов подтверждения, пройденный барьер раздела для взрослого и выпавший в нём арифметический пример.

Для двух случаев простой замены не хватило. Диалог подтверждения покупки хранил объект позиции каталога, диалог снятия — объект предпросмотра: оба заменены на хранение идентификатора и суммы с восстановлением объекта. Результат проверки задания потребовал собственного сохранятеля, который раскладывает его на простые значения.

## Проверка версии 0.2.0: класс ребёнка, ограничения и гардероб

Проверено на эмуляторе `finny_api26` (Android 8.0, API 26) на сборке versionCode 2 / versionName 0.2.0. Профиль создан заново: котёнок «Ryzhik», окрас рыжий, украшение «Бантик», 1 класс.

### Выбор класса при создании профиля

На экране создания питомца появился раздел с вариантами 1–4 класс и пояснением:

```
В каком ты классе
Это нужно только для того, чтобы задания были по силам. Больше ничего о тебе не спрашиваем.
```

### Подбор заданий по классу

Список заданий профиля 1 класса содержит 7 записей и все три обязательные темы ТЗ 2.6:

```
Планирование бюджета
  Раздели монеты на день
  Что не поместится в план
Формирование сбережений
  Сколько не хватает
  Копилка или игрушка
Платежи и покупки
  Что отложить на завтра
  Посчитай сдачу
Как всё исправить
  Помоги Финни
```

Условие задания «Раздели монеты на день» в наборе 1 класса:

```
У Финни 10 монет на день. Корм стоит 4 монеты. Раздели все монеты: сколько на нужное,
сколько на желаемое, сколько в копилку.
```

Это вариант `plan_split_easy` с суммой 10, а не `plan_split` с суммой 30 — отбор по классу работает. Задание на срок накопления `save_rate`, требующее деления, в списке 1 класса отсутствует; вместо него показано `save_gap_easy` («Сколько не хватает»).

Ответ 4 / 3 / 3 принят:

```
Верно! Сначала откладывают на нужное. Корм для Финни важнее игрушки, поэтому его считают первым.
Награда за задание: +10 монет.
```

### Гардероб и покупка украшений

При открытии гардероба на новом профиле стартовое украшение доступно, некупленное — нет. Узлы дерева доступности:

```
text="Бантик — надето"      enabled="true"
text="Шарфик — не куплено"  enabled="false"
```

Это проверка того, что украшение, выданное при создании профиля, записано в таблицу `owned_accessories`: иначе надетое украшение нельзя было бы вернуть после снятия.

После покупки «Шарфика» в каталоге:

```
Купили: Шарфик за 9 монет. У Ryzhik радость выросла на 10.
Что дальше: Теперь это украшение можно надеть в гардеробе.
```

В гардеробе «Шарфик» стал доступен (подпись «— не куплено» снята), кнопка «Перейти в покупки» исчезла, поскольку недоступных украшений не осталось. Смена окраса на серый и украшения на шарфик применилась:

```
Ryzhik переоделся.
```

Подпись под фигурой питомца изменилась с «Малыш, бантик» на «Малыш, шарфик», вид питомца и имя не изменились.

### Один игровой день в календарные сутки

После прохождения дня 1 (план, покупка, «Закончить день», «Начать новый день») главный экран открылся на дне 2 с блоком:

```
День прожит
Сегодняшний игровой день уже закончен. Ryzhik отдыхает и ждёт тебя завтра.
Завтра будут новые монеты и новый план.
```

Узел кнопки «Закончить день» в дереве доступности:

```
<node class="android.view.View" clickable="true" enabled="false" bounds="[42,1605][1038,1731]">
  <node text="Закончить день" class="android.widget.TextView" ... />
```

Значение `enabled="false"` на кликабельном узле подтверждает, что кнопка неактивна. Остальные разделы (задания, покупки, копилка, гардероб, справочник) остались доступны.

Запись в базе данных приложения:

```
adb shell run-as ru.onefortwo.finny.debug sqlite3 databases/finny.db
  select grade,lastFinishedDate,usageDate,usageMinutes,timeLimitEnabled from profile;
1|2026-09-15|2026-09-15|14|1
```

Поле `lastFinishedDate` равно текущей дате — источник блокировки дня.

## Проверка тёмной пары по всем экранам

Проверка выполнена на эмуляторе `finny_api26` (Android 8.0, API 26), отладочная сборка. Тема переключена на «Тёмную» в разделе для взрослого, после чего пройдены все экраны приложения. Тексты снимались `uiautomator dump`, вид — `adb exec-out screencap`.

### Чёрный текст на тёмном фоне в диалогах

Диалог подтверждения покупки выводил заголовок и описание почти чёрным по тёмной подложке. Тот же дефект был у диалогов подтверждения снятия из копилки и подтверждений в разделе для взрослого — все они строятся одним компонентом `AppliqueDialog`.

Причина в месте вызова: диалог вызывается вне `ScreenScaffold`, то есть вне `Surface`, который и назначает цвет текста. Без него `LocalContentColor` остаётся значением по умолчанию — чёрным.

Исправление внесено в сам компонент, а не в каждый экран: `AppliqueDialog` назначает цвет текста явно:

```kotlin
CompositionLocalProvider(LocalContentColor provides MaterialTheme.colorScheme.onSurface) {
```

После пересборки заголовок «Купить «Корм»?», строки «Цена: 10 монет.», «Это нужное.» и «Финни будет сытым» выводятся светлым по тёмной подложке.

### Контур фигуры питомца совпадал с фоном

Контур силуэта рисовался постоянным цветом `#23201A`. В рамке вне сцены фон — `surface`, на тёмной паре это `#1F241A`, то есть контур совпадал с фоном и граница фигуры пропадала. Требование ТЗ 3.6, ради которого контур и введён — граница не должна опираться на цветовой контраст, — на тёмной паре не выполнялось.

Цвет контура вынесен в параметр `drawPet(outlineColor = …)` и берётся у пары через `LocalSceneColors`: на светлой это прежний `#23201A`, на тёмной — `#F0EDE2`. Черты лица (глаза, нос, рот) остались постоянного тёмного цвета: они рисуются по окрасу питомца, а окрасы светлые при любой паре.

Побочный итог: в ночной сцене контур фигуры теперь совпадает по цвету с контурами дерева, облака и линии холмов, которые уже рисовались светлым.

### «Выросла на 0» при полном показателе

Покупка корма при заботе 100 из 100 выводила: «Купили: Корм за 10 монет. У Финни забота выросла на 0.» Показатель упирается в предел, и рост нулевой, но запись читается как ошибка счёта. ### Найдено проверкой правки до фиксации

Правка перед фиксацией проверена независимо: код, сохранение состояния, соответствие документации коду и ТЗ. Подтверждены два дефекта в самой правке.

1. **Экран плана без ползунков.** Правка оставила экран плана в стеке под копилкой, чтобы сохранялись суммы. Но из копилки можно отложить монеты с баланса. Если отложить весь баланс и вернуться, бюджет плана становится нулевым, а ползунок при нулевом максимуме не выводится (`CoinSlider`: `if (max <= 0) return`). Лишние суммы уменьшить нечем. Исправлено: при уменьшении бюджета суммы урезаются до него. Тест `суммы плана урезаются, если бюджет уменьшился, пока план открыт` на коде без исправления падает:

```
java.lang.AssertionError: Failed to assert count of nodes. | Reason: Did not expect any node but found '3' nodes that satisfy: (Text + InputText + EditableText contains '19 монет' (ignoreCase: false))
```

2. **Блок прожитого дня предлагал составить план, когда он уже составлен.** После утверждения плана на следующий день блок продолжал говорить «можно составить план». Исправлено: при утверждённом плане выводится «План на день N составлен: можно делать покупки.» Проверено тестом отрисовки.

Кроме того, неактивность «Утвердить план» и текст причины при копилке без цели теперь проверяются тестом отрисовки, а не только на эмуляторе. Остальные находки касались документации и исправлены в ней.

## Как повторить

```powershell
. scripts/env.ps1
& "$env:ANDROID_HOME\emulator\emulator.exe" -avd finny_api26 -no-window -no-snapshot -no-audio -no-boot-anim -gpu swiftshader_indirect
```

После загрузки системы:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -W -n ru.onefortwo.finny.debug/ru.onefortwo.finny.MainActivity
```

Образ Android 8.0 сохранён в каталоге `tools/`. Виртуальное устройство `finny_api26` хранится в профиле пользователя (`%USERPROFILE%\.android\avd`); на другой машине его нужно создать один раз средством `avdmanager`.
